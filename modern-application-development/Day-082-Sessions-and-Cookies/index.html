📌 Why Sessions and Cookies?

HTTP is stateless. Each request is handled independently, so web applications need mechanisms to maintain state between requests.

Session

Helps an application maintain user-related state across requests.

Cookie

Small browser-stored data that can be sent with matching HTTP requests.

🔄 Authentication Flow

Login → Verify → Login State → Cookie → Future Requests

🔐 Flask Session

from flask import session

session["user_id"] = user.id

user_id = session.get("user_id")

Flask provides the session object for maintaining state across requests.

🧹 Session Operations

Common Flask Session Operations
Operation Code
Set session["user_id"] = user.id
Get session.get("user_id")
Remove session.pop("user_id", None)
Clear session.clear()

🛡️ Protected Route

@app.route("/dashboard")
def dashboard():

    if "user_id" not in session:
        return redirect(
            url_for("login")
        )

    return "Dashboard"

🍪 What is a Cookie?

A cookie is a small piece of data stored by the browser for a website.

Server → Set-Cookie → Browser → Future Request

🍪 Setting a Cookie in Flask

from flask import make_response

response = make_response(
    "Cookie set"
)

response.set_cookie(
    "username",
    "Saloni"
)

return response

📖 Reading a Cookie

from flask import request

username = request.cookies.get(
    "username"
)

🗑️ Deleting a Cookie

response = make_response(
    "Cookie deleted"
)

response.delete_cookie(
    "username"
)

return response

🔒 Cookie Security Attributes

Important Cookie Attributes
Attribute Purpose
Secure Send cookie over HTTPS
HttpOnly Prevent normal JavaScript access
SameSite Control cross-site cookie behavior
Max-Age Specify cookie lifetime in seconds
Path Control URL path scope

⚠️ Flask Default Session

Flask's default session is cookie-based and cryptographically signed. 

app.config["SECRET_KEY"] = os.environ.get(
    "SECRET_KEY"
)

A signed cookie helps detect tampering, but signing does not mean the data should be treated as encrypted secrets.

🧠 Session vs Cookie

Session

  • Maintains application state
  • Useful for login state
  • Flask provides a session object

Cookie

  • Stored by the browser
  • Sent with matching requests
  • Supports security attributes

🔐 Security Rules

HTTPS

Use HTTPS for sensitive authentication traffic.

Secure

Use Secure for sensitive cookies in HTTPS deployments.

HttpOnly

Use when JavaScript does not need access to the cookie.

SameSite

Configure cross-site cookie behavior appropriately.

No Passwords

Never store passwords in cookies or sessions.

Secret Key

Keep the production Flask secret key private.

⭐ Key Takeaways

  • HTTP is stateless.
  • Sessions help maintain application state.
  • Cookies are small browser-stored data.
  • Flask provides the session object.
  • session.get() safely reads session data.
  • session.pop() removes a session value.
  • session.clear() clears session data.
  • Flask can set and read cookies.
  • Secure, HttpOnly and SameSite are important cookie attributes.
  • Passwords should never be stored in cookies or sessions.
