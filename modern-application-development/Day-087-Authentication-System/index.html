📌 Authentication vs Authorization

Authentication

Answers: "Who are you?"

Example: Login with email and password.

Authorization

Answers: "What are you allowed to do?"

Example: Only admins can delete students.

🔄 Authentication Flow

Register → Validate → Hash Password → Store User → Login → Session → Dashboard

👤 User Model

id Primary key
username Unique username
email Unique email
password_hash Hashed password
role Student or Admin

🔑 Password Hashing

from werkzeug.security import generate_password_hash

password_hash = generate_password_hash(password)
Never store plaintext passwords. Store a password hash instead.

✅ Password Verification

from werkzeug.security import check_password_hash

valid = check_password_hash(
    stored_hash,
    submitted_password
)

During login, the submitted password is checked against the stored password hash.

🧑‍💻 User Roles

Student

  • View dashboard

Admin

  • Delete students

🍪 Flask Session

session["user_id"] = user.id

user_id = session.get("user_id")

Sessions allow the application to maintain login state across requests.

🛡️ Protected Route

if "user_id" not in session:
    return redirect(url_for("login"))

A protected route should verify authentication on the server before providing protected resources.

🔐 Flask-Login

LoginManager Manages login configuration.
UserMixin Provides common user-model functionality.
login_user() Logs a user in.
logout_user() Logs a user out.
login_required Protects routes.
current_user Represents the authenticated user.

⚙️ Flask-Login Example

@login_required
@app.route("/dashboard")
def dashboard():
    return render_template("dashboard.html")

🚪 Logout

logout_user()

return redirect(url_for("login"))

With a custom session-based implementation, the application can remove its authentication information from the session.

🛡️ Authentication Security

  • Use password hashing.
  • Never store plaintext passwords.
  • Use a strong secret key.
  • Use HTTPS in production.
  • Validate data on the server.
  • Use CSRF protection for state-changing browser forms.
  • Use generic authentication error messages.
  • Protect admin operations with server-side authorization.
  • Do not log passwords.

⭐ Key Principle

Authenticate first. Authorize second.

Authentication establishes identity. Authorization determines what that authenticated user is allowed to access or modify.
