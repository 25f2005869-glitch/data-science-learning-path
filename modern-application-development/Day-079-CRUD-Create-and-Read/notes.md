# 1. What is CRUD?

CRUD represents four fundamental database operations:

| Letter | Operation | Purpose |
|---|---|---|
| C | Create | Add new records |
| R | Read | Retrieve records |
| U | Update | Modify records |
| D | Delete | Remove records |

This day focuses on:

- Create
- Read

Update and Delete will be covered separately.

---

# 2. Create Operation

The Create operation adds a new record to a database.

In SQL:

    INSERT INTO students
    (name, email, age)
    VALUES
    ('Saloni', 'saloni@example.com', 17);

In SQLAlchemy ORM, we create a Python object.

    student = Student(
        name="Saloni",
        email="saloni@example.com",
        age=17
    )

Then add it to the session.

    session.add(student)

Finally save the transaction.

    session.commit()

---

# 3. SQLAlchemy Create Flow

The basic flow is:

    Create Python Object
            ↓
       session.add()
            ↓
       session.commit()
            ↓
      Database Record

---

# 4. Creating a Model

Example:

    from sqlalchemy import String
    from sqlalchemy.orm import DeclarativeBase
    from sqlalchemy.orm import Mapped
    from sqlalchemy.orm import mapped_column

    class Base(DeclarativeBase):
        pass

    class Student(Base):
        __tablename__ = "students"

        id: Mapped[int] = mapped_column(
            primary_key=True
        )

        name: Mapped[str] = mapped_column(
            String(100)
        )

        email: Mapped[str] = mapped_column(
            String(120)
        )

        age: Mapped[int]

---

# 5. Creating an Engine

The Engine connects SQLAlchemy with the database.

    from sqlalchemy import create_engine

    engine = create_engine(
        "sqlite:///students.db"
    )

For SQLite, the database will be stored in:

    students.db

---

# 6. Creating Tables

After defining the model:

    Base.metadata.create_all(engine)

This creates the required database table if it does not already exist.

---

# 7. Creating a Session

Use a Session to perform database operations.

    from sqlalchemy.orm import Session

    with Session(engine) as session:
        ...

The session manages database interaction and transactions.

# 8. Adding One Record

Example:

    student = Student(
        name="Saloni",
        email="saloni@example.com",
        age=17
    )

    session.add(student)
    session.commit()

After `commit()`, the record is saved.

---

# 10. Why is `commit()` Important?

`session.add()` places an object into the session.

It does not mean that the transaction has been permanently committed.

Use:

    session.commit()

to save the transaction.

Think of it as:

    session.add()
        ↓
    Prepare change

    session.commit()
        ↓
    Save change

---

# 11. What Happens to the ID?

Suppose:

    student = Student(
        name="Saloni",
        email="saloni@example.com",
        age=17
    )

    session.add(student)
    session.commit()

If `id` is an auto-generated integer primary key, SQLAlchemy can populate:

    student.id

after the database insert.

For example:

    print(student.id)

might produce:

    1

# 12. Read Operation

The Read operation retrieves records from a database.

In SQL:

    SELECT * FROM students;

SQLAlchemy uses `select()` to construct a SELECT statement.

    from sqlalchemy import select

    statement = select(Student)

---

# 13. Reading All Records

Use:

    students = session.scalars(
        select(Student)
    ).all()

This returns all Student objects.

You can iterate through them:

    for student in students:
        print(student.name)

---

# 14. Understanding `select()`

Example:

    statement = select(Student)

This means:

    SELECT students FROM Student

Conceptually, it asks SQLAlchemy to retrieve Student records.

The actual SQL generated by SQLAlchemy is database-specific.

---

# 15. Understanding `scalars()`

When selecting ORM entities:

    result = session.scalars(
        select(Student)
    )

`scalars()` gives access to the Student objects rather than row tuples.

Then:

    result.all()

returns all matching Student objects.

---

# 16. `all()`

`all()` returns all matching results.

Example:

    students = session.scalars(
        select(Student)
    ).all()

If there are three records:

    Student 1
    Student 2
    Student 3

then all three are returned.

---

# 17. `first()`

`first()` returns the first matching result.

Example:

    student = session.scalars(
        select(Student)
    ).first()

If no record exists, it returns:

    None

---

# 18. `one_or_none()`

`one_or_none()` returns:

- exactly one matching object, or
- `None` if there is no match.

Example:

    student = session.scalars(
        select(Student)
        .where(Student.email == "saloni@example.com")
    ).one_or_none()

If multiple matching records exist, an exception can occur because the result is not unique.

This makes it useful when the application expects at most one result.

---

# 19. Filtering Records

Use `where()`.

Example:

    statement = select(Student).where(
        Student.age >= 18
    )

    students = session.scalars(
        statement
    ).all()

This retrieves students whose age is at least 18.

---

# 20. Filtering by Name

    statement = select(Student).where(
        Student.name == "Saloni"
    )

    students = session.scalars(
        statement
    ).all()

The condition:

    Student.name == "Saloni"

is converted into a database query condition.

---

# 21. Multiple Conditions

Use SQLAlchemy expressions with logical operators.

Example:

    statement = select(Student).where(
        Student.age >= 18,
        Student.course == "Data Science"
    )

This represents an AND-style condition.

---

# 22. Reading by Primary Key

A convenient method is:

    student = session.get(Student, 1)

This searches for the Student whose primary key is:

    1

If the record does not exist:

    student is None

---

# 23. `session.get()` vs `select()`

### `session.get()`

Use when searching by primary key.

    student = session.get(Student, 1)

### `select()`

Use for general queries and filtering.

    statement = select(Student).where(
        Student.age >= 18
    )

---

# 24. Reading a Specific Column

SQLAlchemy can also select individual columns.

Example:

    statement = select(Student.name)

    names = session.scalars(
        statement
    ).all()

This retrieves student names instead of complete Student objects.

---

# 25. Ordering Results

Results can be ordered.

Example:

    statement = select(Student).order_by(
        Student.name
    )

    students = session.scalars(
        statement
    ).all()

This orders records by name.

---

# 26. Limiting Results

You can limit the number of returned records.

Example:

    statement = select(Student).limit(5)

    students = session.scalars(
        statement
    ).all()

This retrieves at most five records.

# 27. Create + Read Example

Complete basic flow:

    from sqlalchemy import create_engine, select
    from sqlalchemy.orm import DeclarativeBase
    from sqlalchemy.orm import Mapped, mapped_column
    from sqlalchemy.orm import Session

    class Base(DeclarativeBase):
        pass

    class Student(Base):
        __tablename__ = "students"

        id: Mapped[int] = mapped_column(
            primary_key=True
        )

        name: Mapped[str]

        email: Mapped[str]

    engine = create_engine(
        "sqlite:///students.db"
    )

    Base.metadata.create_all(engine)

    with Session(engine) as session:

        student = Student(
            name="Saloni",
            email="saloni@example.com"
        )

        session.add(student)
        session.commit()

        students = session.scalars(
            select(Student)
        ).all()

        for student in students:
            print(
                student.id,
                student.name,
                student.email
            )

# 28. Transaction and Rollback

If an operation fails, rollback can be used.

    try:
        session.add(student)
        session.commit()

    except Exception:
        session.rollback()
        raise

The basic idea is:

    Successful operation
            ↓
         commit()

    Failed operation
            ↓
        rollback()

# 29. Create and Read in Flask

With Flask-SQLAlchemy:

    from flask import Flask
    from flask_sqlalchemy import SQLAlchemy

    app = Flask(__name__)

    app.config[
        "SQLALCHEMY_DATABASE_URI"
    ] = "sqlite:///students.db"

    db = SQLAlchemy(app)

Model:

    class Student(db.Model):
        id = db.Column(
            db.Integer,
            primary_key=True
        )

        name = db.Column(
            db.String(100),
            nullable=False
        )

Create:

    student = Student(
        name="Saloni"
    )

    db.session.add(student)
    db.session.commit()

Read:

    students = db.session.execute(
        db.select(Student)
    ).scalars().all()

# 31. Common Mistakes

### Mistake 1 — Forgetting commit

    session.add(student)

without committing may leave the transaction uncommitted.

### Mistake 2 — Using the wrong model

Make sure the query targets the correct model.

### Mistake 3 — Not handling `None`

For example:

    student = session.get(Student, 100)

The record may not exist.

Check:

    if student is None:
        print("Student not found")

### Mistake 4 — Assuming `first()` means unique

`first()` simply returns the first matching result.

It does not guarantee uniqueness.

### Mistake 5 — Assuming `one_or_none()` allows duplicates

If multiple records match, `one_or_none()` can raise an exception.

---

# 32. Best Practices

- Use meaningful model names.
- Define proper primary keys.
- Use constraints such as `unique` where appropriate.
- Validate input before creating records.
- Commit intentional changes.
- Handle failed transactions.
- Check for `None` when a record may not exist.
- Use `session.get()` for primary-key lookup.
- Use `select()` for flexible queries.
- Avoid unnecessary database queries.
- Keep database logic organized.
