📌 What Is Database Design?

Database design is the process of organizing data into meaningful tables, choosing columns and data types, and defining relationships and constraints.

🧩 Basic Database Concepts

Database Organized collection of data.
Table Stores related records.
Row Represents one record.
Column Represents an attribute.
Entity Object about which information is stored.
Attribute Property of an entity.

🔑 Primary Key

A primary key uniquely identifies each row in a table.

id INTEGER PRIMARY KEY

Example: student ID 1 identifies one particular student record.

🔗 Foreign Key

A foreign key connects a record in one table to a record in another table.

FOREIGN KEY (student_id) REFERENCES students(id)

SQLite foreign-key enforcement should be enabled on the connection when the application relies on foreign-key constraints.

PRAGMA foreign_keys = ON

🛡️ Common Constraints

Constraint Purpose Example
PRIMARY KEY Uniquely identifies a row id INTEGER PRIMARY KEY
NOT NULL Prevents NULL values name TEXT NOT NULL
UNIQUE Prevents duplicate values email TEXT UNIQUE
DEFAULT Provides a default value status TEXT DEFAULT 'active'
CHECK Enforces a condition marks INTEGER CHECK (marks >= 0)
FOREIGN KEY Connects related tables REFERENCES students(id)

🏗️ Create a Student Table

CREATE TABLE students ( id INTEGER PRIMARY KEY, name TEXT NOT NULL, email TEXT UNIQUE, marks INTEGER CHECK (marks >= 0 AND marks <= 100) );

📚 Course Table

CREATE TABLE courses ( id INTEGER PRIMARY KEY, name TEXT NOT NULL, credits INTEGER CHECK (credits > 0) );

🔄 Many-to-Many Relationship

A student can take many courses, and a course can have many students. This is a many-to-many relationship.

Students
↓
Enrollments
↓
Courses

🧩 Junction Table

CREATE TABLE enrollments ( student_id INTEGER, course_id INTEGER, PRIMARY KEY (student_id, course_id), FOREIGN KEY (student_id) REFERENCES students(id), FOREIGN KEY (course_id) REFERENCES courses(id) );

🔢 Composite Primary Key

A composite primary key uses multiple columns together to identify a record.

PRIMARY KEY (student_id, course_id)

In an enrollment table, this can ensure that the same student is not enrolled in the same course more than once.

🧠 Relationship Types

One-to-One

One record relates to one record.

Example: Student ↔ Profile

One-to-Many

One record relates to many records.

Example: Course → Students

Many-to-Many

Many records relate to many records.

Example: Students ↔ Courses

📐 Normalization Basics

Normalization organizes data to reduce unnecessary duplication and improve consistency.

Avoid designs with repeated columns such as: course1, course2, course3. A separate course table and enrollment relationship can be more appropriate.

⭐ Good Database Design Rules

  • Use meaningful table names.
  • Use meaningful column names.
  • Define primary keys.
  • Use foreign keys for relationships.
  • Choose appropriate data types.
  • Use constraints where appropriate.
  • Avoid unnecessary data duplication.
  • Use junction tables for many-to-many relationships.
  • Test the design with realistic sample data.
